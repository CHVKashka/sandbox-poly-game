# Планы и известные ограничения

Список — идеи и очевидные следующие шаги, не обязательства. Порядок ориентировочный.

## Покраска по граням — сделано (2026-09-27)

Paint красит одну грань клетки под курсором (`VoxelGrid.TryPaintFace`/`GetFaceColor`, `RayHit.Normal` определяет
какую), не весь `BlockInstance` и не всю клетку — выбран более дорогой из двух обсуждавшихся вариантов ("по грани",
не "по клетке"), см. [WORKLOG.md](WORKLOG.md) за 2026-09-27 (5). Не сделано (сознательно отложено): точечная
покраска наклонных/треугольных граней форм (Wedge/Pyramid/InvertedPyramid красятся такими гранями только целиком) и
персистентность точечной покраски в Save/Load JSON (`ConstructionIO` хранит только представительный цвет экземпляра;
`Ctrl+Z`/`Ctrl+Y` её видят, файл — нет).

## Редактор построек — ближайшее

- **Список сохранённых конструкций** (окно с превью/именами файлов из `user://Constructions`) поверх уже готового
  Save/Load (см. [03-build-editor.md](03-build-editor.md)).
- **Resize с перетаскиванием мышью** (live-превью размера при зажатой ПКМ на грани, без панели на тулбаре) — сейчас
  размер меняют кнопки «+»/«−» или текстовое поле на панели (см. [03-build-editor.md](03-build-editor.md)), по 1
  клетке за клик/значение за раз.
- **Изменение уже поставленных блоков** — Resize (размер), `J`/`K`/`L` (поворот) и `U`/`I`/`O` (отражение) сейчас
  настраивают только ПРИЗРАК — то, что встанет следующим по ЛКМ (`EditorState.PendingSize`/`PendingRotationSteps`/
  `PendingMirror`); ни один из них не действует на уже стоящий блок (см. [03-build-editor.md](03-build-editor.md)).
  Потребует отдельного режима выбора цели (наподобие прежней, ПКМ-based версии Resize) или нового инструмента.
- Произвольные (не только 90°) повороты и не-осесимметричные формы (готовая геометрия — фиксированный набор вершин
  на класс формы, см. `Scripts/Core/BlockGeometry.cs`).
- **Скосы/пирамиды: полные (не наклонные/треугольные) грани теперь культятся и склеиваются — сделано (2026-09-27)**,
  см. [WORKLOG.md](WORKLOG.md) (5). Оставшийся scoped-гэп: культинг/склейка наклонных/треугольных граней при точном
  геометрическом совпадении с соседом (например, двух зеркальных скосов, формирующих общий конёк крыши) не сделаны —
  нужны таблицы совпадения по форме/повороту/отражению, отдельный более поздний шаг, если понадобится.
- **Коллизия для физики**: у растянутых блоков сейчас есть только занятая область клеток (используется рейкастом
  редактора и мешингом) — настоящих `CollisionShape3D` нет, т.к. в игре вообще пока нет физики (см. «Игра» ниже).
- **Инструменты**: выделение области/копирование, заливка (перекраска связной области), «пипетка» (взять цвет/блок
  под курсором), удаление/установка прямоугольником.
- **Настройки**: чувствительность мыши, скорость камеры, альтернативная клавиша поворота камеры (сейчас только СКМ).
- **Каркас** с толщиной (линии-квады), настраиваемый цвет.
- Опционально: удаление внутренних граней в **полностью замкнутых полостях** (сейчас строятся, снаружи не видны).

## Игра

- Свойства блоков (`BaseComponent`: масса, прочность, сопротивление урону) уже хранятся на каждом блоке, но пока
  ни на что не влияют — нужны расчёт центра масс/объёма постройки, повреждения, плавучесть.
- Переход из редактора в мир: запуск конструкции с физикой (транспорт) — потребует настоящих `CollisionShape3D`
  на экземпляры блоков (см. выше).
- Большие миры на double precision (ради этого и собран движок): проверка точности вдали от начала координат,
  плавающее начало координат не нужно.
- Мультиплеер: сервер и клиенты должны быть собраны с одинаковой точностью (double).
- Локализация UI (сейчас строки на английском прямо в коде).

## Инфраструктура

- Экспорт игры: собраны шаблоны double+mono, настроить пресет экспорта с ними (Custom Export Templates).
- CI/скрипт: одной командой собирать движок и прогонять самотесты на новом устройстве.
- Если понадобятся GDExtension — их нужно собирать с `precision=double` и `REAL_T_IS_DOUBLE`.
