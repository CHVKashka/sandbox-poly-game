# 03. Редактор построек

Первая часть игры: редактор, в котором строится конструкция из блоков (как в редакторе транспорта Stormworks).
Главная сцена проекта — `Scenes/BuildEditor.tscn` (скрипт `Scripts/Editor/BuildEditor.cs`).

## Реализованные требования

| # | Требование | Реализация |
|---|---|---|
| 1 | Камера на WASD | `FlyCamera`: WASD вдоль взгляда/вбок, Q/E вниз/вверх, Shift — быстрее, Ctrl — медленнее; поворот — зажатая СКМ |
| 2 | Хотбар на 9 слотов, Tab — список блоков | Хотбар внизу по центру (клавиши 1–9, колесо, клик). Tab открывает окно всех блоков; клик по блоку кладёт его в выбранный слот |
| 3 | Тулбар справа: цвет, удаление, wireframe | Панель «Tools»: **Paint** (+ выбор цвета и палитра из 12 цветов), **Delete**, **Wireframe** (3 режима) |
| 4 | Блоки ставятся на ПКМ | ПКМ ставит блок из выбранного слота в клетку под курсором (с полупрозрачным «призраком» заранее) |
| 5 | Склейка полигонов, единый wireframe, без внутренних граней | Отсечение граней между соседними блоками + жадное слияние копланарных граней; каркас строится только по «настоящим» рёбрам формы (см. ниже) |

## Управление

| Действие | Ввод |
|---|---|
| Движение камеры | `W` `A` `S` `D` (вперёд/влево/назад/вправо вдоль взгляда) |
| Вверх / вниз | `E` / `Q` |
| Быстрее / медленнее | `Shift` ×4 / `Ctrl` ×0,25 (базовая скорость 4 м/с) |
| Поворот камеры | зажать **среднюю кнопку мыши** и двигать мышь |
| Поставить блок | **ПКМ** |
| Применить инструмент (перекраска/удаление) | **ЛКМ**; при зажатой ЛКМ инструмент применяется ко всем блокам, над которыми проводится курсор |
| Выбор слота хотбара | `1`–`9`, колесо мыши (по кругу), клик по слоту |
| Список всех блоков | `Tab` (закрыть — `Tab`, `Esc` или клик по затемнению) |

Клавиши читаются по **физическому** положению, поэтому работают в любой раскладке (RU/EN).
Инструменты тулбара переключаются кликом (повторный клик выключает). ПКМ ставит блок независимо от выбранного инструмента.

## Интерфейс

- **Хотбар** — 9 слотов, в каждом цвет и название блока; выбранный слот подсвечен рамкой. По умолчанию заполнен первыми девятью блоками.
- **Список блоков (Tab)** — сетка карточек всех блоков из `BlockRegistry` (сейчас 12). Хотбар и тулбар остаются доступны поверх затемнения.
- **Тулбар (справа)** — Paint / выбор цвета (`ColorPickerButton` + палитра) / Delete / Wireframe.
  Wireframe циклически переключает режимы: **off** (только грани) → **overlay** (грани + линии каркаса) → **only** (только каркас).
- **Инфо-строка (слева сверху)** — подсказка по управлению и статистика: число блоков, число полигонов после склейки
  и до неё («faces before merge»), число отрезков каркаса, чанки, клетка под курсором, FPS.
- **Курсор**: полупрозрачный «призрак» блока в клетке, куда встанет блок; при активном инструменте — контур блока под
  курсором (красный для Delete, цвет краски для Paint).
- **Земля** — сетка на плоскости `y = 0` (клетка 0,25 м, жирные линии каждый метр, красная ось X, синяя ось Z);
  по ней можно ставить первые блоки. Клик мимо построек и мимо земли ничего не делает.

## Сетка и данные

- Одна клетка = один блок = **0,25 м** (`BuildSpace.CellSize`). Клетки — целые `Vector3I`; клетка `(x,y,z)` занимает
  мировой куб `[x·0,25 … (x+1)·0,25]` и т.д.
- Область построек: клетки `X,Z ∈ [-128, 127]`, `Y ∈ [-64, 191]` (64×64×64 м). Вне области ставить нельзя.
- Хранилище `VoxelGrid` — разреженный словарь **чанков 16×16×16** (`VoxelChunk`: `ushort[] Ids` — тип блока, 0 = пусто;
  `uint[] Colors` — цвет клетки RGBA8). Тип блока и цвет независимы: перекраска не меняет тип.
- Изменения (`TrySet` / `TryRemove` / `TryPaint`) генерируют событие `CellChanged`; `VoxelWorld` помечает «грязными»
  затронутые чанки и раз в кадр пересобирает их меши. Затронуты: чанк клетки и соседи по тем границам, на которых клетка
  лежит (`VoxelGrid.GetAffectedChunks`) — соседние грани и рёбра каркаса зависят от клетки через границу чанка.
  Полнота этого набора проверяется самотестом (случайные правки на границах чанков).

## Меширование (`ChunkMesher`)

Результат для чанка — вершины в метрах **относительно угла чанка** (узел `MeshInstance3D` стоит в углу чанка; так
точность не зависит от расстояния до начала координат).

1. **Отсечение**: грань клетки создаётся, только если по нормали нет соседнего блока. Внутренние грани между
   блоками не строятся вообще. Соседи берутся из «рамки» в 1 клетку вокруг чанка, поэтому границы чанков не дают лишних граней.
2. **Склейка (greedy meshing)**: для каждой из 6 сторон и каждого слоя строится маска цветов видимых граней; смежные
   грани **одного цвета** в одной плоскости объединяются в максимальные прямоугольники. Склейка не зависит от типа блока —
   только от цвета (два разных блока одного цвета сольются в общий полигон). Склейка идёт внутри чанка.
3. **Порядок вершин**: Godot считает лицевой стороной ту, с которой вершины идут **по часовой стрелке**;
   порядок зависит от знака нормали. Самотест проверяет для каждого треугольника, что `(b−a)×(c−a)` направлен против нормали.
4. Один чанк — один `ArrayMesh` с вертекс-цветами (одна поверхность, один материал → один draw call на чанк).

Результаты: демо-дом 1622 блока → 217 полигонов (3196 граней до склейки); плита 80 000 блоков → 160 полигонов (23 200 граней).

## Единый wireframe

Каркас — отдельный линейный меш (`Mesh.PrimitiveType.Lines`), а **не** встроенный wireframe-режим Godot
(тот рисует все рёбра треугольников, включая диагонали и швы).

Правило «настоящего ребра». Каждое единичное ребро сетки окружено четырьмя клетками (в плоскости, перпендикулярной ребру).
Ребро показывается, только если заполнено:
- **ровно 1** клетка (выпуклый угол), или
- **ровно 3** клетки (вогнутый угол), или
- **2 клетки по диагонали** (вырожденный случай).

Не показываются: 0 или 4 заполненных клетки (пустота/внутренность) и **2 соседние клетки** — это шов внутри плоской
поверхности. Поэтому каркас:
- не зависит от цвета и типа блоков (перекраска его не меняет);
- не зависит от границ чанков и склейки полигонов;
- содержит только контур и изломы формы — «единый wireframe постройки».

Технические детали:
- Каждым ребром владеет ровно один чанк — тот, где лежит его начальный узел; дублей и пропусков на границах нет
  (сверка с независимым подсчётом «в лоб» в самотесте на случайной постройке через границы чанков и отрицательные координаты).
- Подряд идущие одинаковые единичные рёбра вдоль оси сливаются в один отрезок.
- Линии сдвигаются наружу на 4 мм (`WireOffsetMeters`) вдоль направления «от заполненных клеток», иначе они мерцают
  (z-fighting) на самих гранях.
- Линии 1 px, цвет светло-голубой; в режиме «only» грани скрыты.

## Рейкаст (`VoxelRaycaster`)

Точный обход клеток лучом (Амануидес–Ву) без физики и коллайдеров; луч строится из камеры через позицию курсора.
- Попадание в блок: `BlockCell` — блок, `PlaceCell = BlockCell + Normal` — куда ставить новый.
- Попадание в землю (`y = 0`, граница клеток): блока нет, `PlaceCell` — клетка **над** плоскостью (для камеры выше земли)
  или **под** ней (для камеры ниже). Вне области построек земля не «ловится».
- Камера внутри блока не считает стартовую клетку попаданием.
- Границы клеток пересчитываются заново на каждом шаге (а не накапливаются), а клетка на земле берётся из самой точки
  пересечения: накопление ошибки округления раньше давало «землю» на клетку ниже плоскости (`y = -1`).

## Ввод и UI

- Клавиши и колесо обрабатываются в `_Input` (до GUI): `Tab` иначе ушёл бы в навигацию по элементам UI; все кнопки UI
  дополнительно имеют `FocusMode = None`.
- Клики по миру — в `_UnhandledInput`: GUI забирает клики по своим элементам сам. Дополнительно
  `EditorUi.IsPointOverUi` (прямоугольники хотбара/тулбара, либо открытый список блоков) не даёт лучу строиться под UI.
- Поворот камеры: нажатие СКМ включает `MouseMode.Captured`, отпускание/потеря фокуса окна возвращают курсор.
  Позиция курсора для лучей берётся из событий мыши (`_mousePosition`), поэтому работает и с имитированными событиями.
- Перетаскивание инструмента: новый блок обрабатывается, только если мышь **сдвинулась** — иначе после удаления цель
  «перескакивала» бы на следующий блок и удаление проедало постройку насквозь при неподвижной мыши (проверено тестом).
- Пересборка мешей и обновление курсора идут в `_Process`; статистика в инфо-строке — 4 раза в секунду.

## Рендер

- Материал граней: `StandardMaterial3D` с вертекс-цветами как albedo, цвета трактуются как sRGB (`VertexColorIsSrgb`).
- Освещение: процедурное небо, направленный свет с тенями (2 каскада, 40 м) — облегчено для встроенных видеокарт.
- Сетка земли — `Shaders/build_grid.gdshader` (процедурные линии с антиалиасингом, затухание по расстоянию, оси X/Z).
- В проекте включён MSAA 2× (`project.godot`).

## Как расширять

- **Новый блок**: добавить запись в `BlockRegistry` (`Id`, имя, цвет по умолчанию) — появится в списке по Tab.
  Все блоки пока — полные кубы; отличаются типом (заготовка под массу/прочность) и цветом.
- **Новый инструмент**: значение в `ToolMode`, кнопка в `ToolbarUi`, ветка в `BuildEditor.UseToolAtHover`.
- **Новая форма блока** (клин, скос, плита): потребует «маски граней» на блок (частичное закрытие соседней грани) в
  `ChunkMesher` и правил для каркаса — см. [ROADMAP.md](ROADMAP.md).

## Ограничения текущей версии

- Все блоки — кубы 0,25 м; нет ориентации блоков.
- Нет отмены/повтора, сохранения/загрузки построек, выделения областей, симметрии.
- Замкнутые полости внутри постройки строят внутренние грани (они не видны снаружи, но существуют);
  сознательно не удаляются, чтобы «комнаты» были видны изнутри.
- Поворот камеры только на СКМ (у мышей без СКМ поворота нет).
- Каркас — линии в 1 px (без толщины).
